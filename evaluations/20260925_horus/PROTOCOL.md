# Horus 预注册评估方案（2026-09-25）

本方案在正式检索实验前写入。目标为检验收益与代价，不以证实有效为目标。主代码固定为 `5616fc9afe55b38e135365c8448e373d7900e832`；本目录新增独立入口，不修改产品逻辑。历史数字只核对，不计入本次结果。

## 数据与权限

- 60 道正式题，六类各 10 题；另有 6 道开发题，不进入正式分母。
- 自然资料：仓库 MIT 项目的 README、优化说明、配置和源代码，40 题（事实、整合、条件、错误前提）。文档是被评资料，不是效果真值。
- 合成资料：10 道双来源冲突、10 道缺少属性的无答案题。政策名称和值纯属虚构，与自然资料分层报告。冲突题的可回答性指“能回答两种说法及无法确定”，不要求强选唯一值。
- 题目由 AI 助手对照来源构建；原文位置程序逐条验证；尚无人类独立复核。允许等义表达，不允许改变数值、单位、条件或来源关系。参考答案与 evidence 均保存。
- 30 条独立核查挑战：每个合成单事实上下文对应支持/矛盾/证据不足各一条，独立参考标签先于调用确定；这些简单案例不能代表自然复杂回答。
- 不读取或上传个人简历、原始私有知识库、历史纠偏记忆或密钥文件。测试语料和向量库完全独立。无外部搜索进入主实验。

## 对照与控制

- A：相同 BGE 向量模型，Chroma 原始 Top-5，无重排或相关度门槛，再用产品生成节点。
- B：产品 HybridRetriever，向量20 + BM25 20 → RRF → 重排10 → 阈值0.3 → Top-5，再用相同生成节点。
- C：**复用 B 的逐字初始回答和同一份编号上下文**，增加产品核查节点及最多一次重写、再核查。这样排除再次随机生成的影响。C 成本为 B 成本加真实增量调用；不会重复计费 B。该实验是固定初始答案上的增量机制评估，不是两个独立应用会话的时延对照。
- V（诊断，不生成）：向量 Top-10 → 相同重排与阈值 → Top-5。B−V 更接近候选融合贡献；B−A 是整套检索配置比较，不能只称为 BM25 收益。
- D 暂不纳入，避免增加费用且不影响核心问题。
- 产品默认主模型 deepseek-chat；轻模型 Qwen/Qwen2.5-7B-Instruct 用于核查和重写。若正式调用使用它们，C−B 同时含不同模型及额外计算，不能宣称同一模型纯算法贡献。禁用主备自动切换，记录响应 model / fingerprint（服务未返回版本时标记不可固定）。生成 temperature=0.1、max_tokens=512；不使用记忆、会话历史、查询改写、HyDE、联网；stream=false 以便精确保存 usage（与产品流式延迟不可直接比较）。
- 本地实验单进程单并发、CPU线程4，模型缓存离线使用。新建独立 Chroma 索引。冷初始化和开发题预热单列；正式请求无结果缓存，复用模型与数据库实例，随机问题及 A/B/V 顺序（seed=20260925），重复3轮。重复是稳定性检查，不把180次当180个独立问题；统计单位仍为60题。
- 真实 LLM 在预算允许后仅单轮，声明随机性限制。并发1、SDK重试0、单请求超时采用配置，错误保留；连续3次网络/服务失败停止，剩余题标记未执行。不得自动选择表现最佳的配置。

## 指标及分母（先固定）

### 检索（本次可离线实测）

证据匹配规则：原文 quote 去除空白后，在指定 source 的返回 chunk 中连续出现。标签粒度是原文证据单元而非完整文档。少量跨分块原文必须在运行前校验能被至少一个 chunk 覆盖，否则报错并记录数据修订。局限：未穷尽同义/重复证据会低估召回，不能当成答案判分。

- 任一证据命中率：有答案50题中至少命中一个证据单元的比例。
- 完整证据命中率：50题中所有标注证据单元均命中的比例；对冲突题必须两方均命中。
- 证据单元召回：每题命中证据单元数/参考证据单元数，50题宏平均。
- 标注 chunk Precision@5：命中任一标注原文的返回块数/5；返回精度的分母为返回块数；两者不是业务语义相关性真值。
- MRR：首个命中标注证据位置的倒数，未命中为0；50题宏平均。
- 无答案题空结果率：无答案10题中成功返回空列表比例；不是生成拒答率。原始向量强制Top-5的结构性劣势必须说明。
- 有答案题空结果率：50题中成功返回空列表比例；它触发当前产品固定拒答，但不能等同于完整 LLM 实验的误拒答率。
- 异常题保留，总体检索指标按0计；错误不算正确空结果；另报仅成功样本的指标及成功数。

### 回答、核查与纠正（需要真实调用和独立评分）

- 答案正确性：正确=1（所有关键事实正确、无关键错误且满足拒答/冲突/纠前提要求）；部分=0.5（至少一个关键事实正确，无关键矛盾但有遗漏）；错误=0（关键错误、无正确事实或有答案全拒答）。无答案必须明确缺失且不编造才为1，无0.5。冲突只给一方当唯一结论为0，列双方但不表不确定为0.5。总体分母60，失败/未完成在整体可用性口径为0，成功质量另报；若整组尚未运行则指标为NA，不能填0。
- 关键事实完整性：独立评分覆盖的事实数/参考事实数；对可回答50题宏平均，无答案题NA。回答正确率、事实覆盖和拒答必须共同报告。
- 忠实度：独立拆分可核验事实，分别标支持、矛盾、资料不足。各类陈述数/全部已审计事实性陈述数；无事实的拒答不赋100%忠实度，记NA。同时记录每题和微平均。不得将不足等同于事实错误。
- 引用：程序检查编号存在率；独立评分检查来源是否正确、引用是否支持对应陈述。存在有效编号不代表语义支持。分别报告含引用事实比例、引用有效率、引用支持率，分母显式记录。
- 无答案正确拒答率：10题；有答案误拒答率：50题；冲突处理正确率：10题，单独分层。
- 核查混淆矩阵：30条独立挑战的固定参考标签对实际标签，三类各10。记录 missing / error 为第四预测列，计入各类召回分母；分别精确率、召回、F1。不用核查器的输出充当参考。自然回答核查还需外部标注逐条对齐，未做则NA。
- 纠正：同题 B→C 的正确/部分/错误转移矩阵；错→对、对→错、分数上升/下降/持平；所有题和真正重写子集分别报告。保存 B 原文、C 原文及所有核查轮次。错误导致无法输出时计失败，不悄悄剔除。
- 开销：端到端耗时 P50/P95、成功与全部样本分别统计；B原始耗时+C增量用于C口径。输入/输出token以API usage为准，缺失为unknown；调用次数含失败，重试次数单列。无可信实时单价时不报货币成本。

## 评分偏差及统计

- 字面证据匹配只评检索；不拿关键词匹配代替答案正确性、忠实度、核查准确性。
- 评分者看随机 answer_id、问题、参考事实和上下文，不看方案名或核查器判定。若调用独立模型，保存固定 rubric、请求、模型标识、原始响应，明确模型评分非人工真值。若只有同模型可用，须单列相关偏差，不能作为独立核查证据。
- 待人工复核 CSV 覆盖题型、命中/漏检、拒答、冲突；真实回答产生后补充正确/错误/改好/改坏分层。human 字段始终为空直至真实人工填写。
- 配对 bootstrap：按题抽样10000次，seed=20260925，95%百分位区间；先对各题3轮求均值，再算配对差。正式题不用于阈值/Prompt调参。该区间只反映此构造题集的题间波动，不代表业务总体泛化。

## 预算门槛

本轮先做免费本地检索和 Prompt 长度试跑。API密钥内容不读取；只记录进程环境变量是否存在以及 .env 文件是否存在。未注入的环境变量不能视为服务可用。真实调用及联网须预算授权，并通过安全进程环境配置。调用清单、基于真实检索上下文的代理token估算会单独输出；代理token不是供应商计费token。授权前不启动批量付费调用。
