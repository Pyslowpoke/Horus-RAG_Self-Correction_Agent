# 实现审计与可测范围

## 代码路径与实际行为

| 功能 | 当前实现 | 评估处理 |
|---|---|---|
| 路由 | `src/agents/router_agent.py` 关键词与显式模式规则 | 固定 local；不声称自主规划或并行多 Agent |
| 检索 | `HybridRetriever`：向量/BM25、去重、RRF、重排/门槛 | 真实本地模型 A/B/V 三轮 |
| 生成 | GenerationAgent，空证据固定拒答，否则调用主模型 | A/B 使用相同提示模板、temperature、512输出上限 |
| 核查 | FactChecker 输出三类标签；检查JSON与证据原文是否存在 | C真实调用；另30个独立参考挑战；程序契约探针另列 |
| 纠正 | graph 的 rewrite 节点调用核查客户端，最多一次 | C复用B原文，保存完整轮次；不重新检索 |
| 记忆 | 向量纠偏记忆+文件监听，追加生成提示 | 排除：原库可能含私人资料，避免题目污染 |
| HyDE | 默认关闭；原查询无证据时才调用 | 固定关闭 |
| 外部搜索 | 百度千帆；混合模式无本地结果才调用；摘要证据 | 主实验关闭；真实联网未评估，现有模拟测试覆盖错误分支 |
| UI | Streamlit后台任务、草稿流式、时限、结果缓存 | 原有AppTest真实运行，但模型/网络为替身；不当作真实E2E性能 |

## 原评估工具的边界

`experiments/evaluate_accuracy.py` 已按证据ID或原文匹配评检索。Precision@K分母是K，returned_precision分母是实际返回数；Recall分母是匹配到的所有标注块；MRR是第一个匹配块的倒数。它不生成答案、不评语义忠实度、不评核查分类，也不会证明减少幻觉。无答案的 correct_abstention 仅表示返回空文档。原脚本遇到未命中标注或运行异常会终止，没有完整的逐题失败统计。

本次增加独立入口以保留每题结果、候选、错误、多个证据单元、各题型与配对区间；不改变生产检索器。`experiments/test_data.py` 仍是旧关键词示例，不是足以支持“防止幻觉”的事实标注集。

README 的历史表明确写了小样本和未实测真实API；不能合并到本次样本，也不能当作答案准确率。后续报告只引用本目录新运行数据。当前README未给真实核查收益，因此“事实核查提升准确率/降低幻觉X%”没有旧证据支撑。

## 程序契约探针

`checker_contract_probes.json` 是6个真实执行的程序分支探针，输入的LLM输出为人为预设。能证明程序如何处理一种输出，不能测出真实模型发生概率：

- 非法JSON → error；不存在的证据原文 → failed：防护分支正常。
- 引用真实原文但标签逻辑错误 → passed：原文存在不等于蕴含。
- 核查器漏掉第二条错误陈述 → passed：缺少陈述覆盖校验。
- 事实回答却返回空数组 → no_claims：图不触发重写，仍需独立核查覆盖监测。

## 修改与预算记录

产品 `src/`、`app.py`、配置及Prompt均未修改；新增内容只在独立评估目录。未做基于正式题的调参。初始启动仅检查进程/用户/系统环境变量，均缺失；用户指出`.env`后，按其授权增加 `--load-project-env`，仅进程内加载用于认证，未把密钥传给评估模型或写入日志。

开发题预算最多26次，实际20次；正式最多290次，独立授权保存在对话与 `PAID_PILOT_REVIEWED.json`。真实费用单价未确认，报告调用量/usage，不估造人民币价格。网络失败无重试，连续3次失败停机；失败保留，不替换原结果。

## 时延与能力结论的口径

本地检索时间是真实请求耗时，冷初始化和预热另列。API阶段重放固定检索上下文，用实际产品图运行生成、核查和纠正；实测的是该固定证据图耗时。把已测检索耗时与图耗时相加只能称“组件合成耗时”，不能冒充一次真实Streamlit端到端计时。C的公平时延是B原图耗时加C新增核查/修正图耗时；B首次生成只计费一次。

语料是项目说明加合成制度，不能代表真实研究任务、互联网检索或私有业务数据。所有人工复核待完成。AI评分由同一编程助手执行，存在作者偏差；匿名输入降低但不消除方案可推断性。
